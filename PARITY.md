# Parity: the Rust itm against the Python itm

Where the Rust itm (the crate at the repository root) stands against
every requirement in `REQUIREMENTS.md` and every rule in `DESIGN.md`
section 2. The Python itm 0.2.0 was the behavior reference: its package
and tests (`inbox_task_manager/`, `tests/*.py`) left the tree at the
cutover (milestone 5) and are at commit 7bdbaa4, the rewrite's base;
`scripts/cross-check.sh` runs a pinned build of it and the Rust itm on
shared state. Updated with every change that moves a row.

Status: **done** (behaves like the Python itm, pinned by a test), **partial**
(what is missing is said), **missing**, **n/a**. Tests are named
`module::test` for unit tests in `src/`, `switching::test` for the
real-process tests in `tests/switching.rs`, and `cross-check`, `smoke` for
the scripts in `scripts/` (run in a sandbox against the Python build and a
real headless Herdr; at milestone 5, cross-check 434 of 434, smoke 128 of
128 with Herdr 0.9.3 and with 0.9.5).

Last updated: milestone 5 (parity audit and cutover).

## Known differences from the Python itm

- Herdr is reached over its socket API, not the CLI, and a session is
  stopped with `server.stop` (DESIGN.md section 4, 2026-11-06).
- `itm list` writes `tasks.json` only when it adopts a session or expires
  a tombstone; Python writes on every list (the content is the same).
- Project names refuse only control characters (Unicode Cc); Python
  refuses all of category C (format characters such as zero-width spaces
  too).
- `~user` in `ITM_PROJECTS_DIR` is not expanded (Python's `expanduser`
  does).
- `itm edit --add-project api --add-project API` adds api once and says
  so once; Python logs and reports it twice.
- A deleted task's session is stopped over the socket, and a detached
  shell runs `herdr session delete` until the server is gone (up to
  15 s); Python runs `herdr session stop` and `herdr session delete` once.
- System errors read as Rust words them ("Permission denied (os error
  13)"), not as Python does ("[Errno 13] Permission denied: '…'"), for
  example in "could not update its notes: …". A `$VISUAL` that does not
  split like a shell line names no Python exception in its error.
- In git URLs, like project names, only control characters (Unicode Cc)
  are refused in a path segment; Python refuses all of category C. A URL
  whose host has IPv6 brackets is refused (Python takes an IPvFuture host).
- Settings are changed as a TOML document (toml_edit): quoted keys, dotted
  keys (`herdr.projects_from_workspaces = false`) and inline tables are
  edited, where Python refuses them with "edit it by hand". A TOML syntax
  error is worded as toml_edit says it, on one line ("unclosed table,
  expected `]` (at line 1, column 7)"); Python words it as tomllib does.
  A file that is not UTF-8 says Rust's error ("stream did not contain
  valid UTF-8").
- The daemon asks each running task session once per pass
  (`session.snapshot`: its agents and its workspaces' folders); Python runs
  `herdr agent list` and `herdr api snapshot`. When the snapshot fails,
  neither agents nor workspaces are read for that session on that pass.
- The add dialog checks what was typed as adding checks it, so a folder
  named like a project without a folder says "has no folder yet; give it
  this one" while typing; Python says "project already exists: … (no
  folder); choose another name" until Enter. It is filled with a folder
  as `~/…`. Esc waits for a folder or a name being saved (milliseconds);
  Python closes the dialog and the save still happens.
- The form's snooze is a field ←/→ change (Textual's `Select` is a
  drop-down); typing on it picks "Other time…" and types the time there.
- No mouse: the project field, rows and tabs are not clickable (Textual's
  are). A paste (bracketed paste) is typed, whitespace one space each,
  except into the form's description, which keeps its lines.
- The Projects screen sizes its columns to what is in them and lets the
  column of where a project is give way (and go) in a narrow popup, so
  when it was last used is never cut; Python's columns are fixed (14, 45
  and 16 wide). Key hints in the forms, the finder, the add dialog and the
  Projects screen wrap whole, a line each as needed. A field's value
  longer than the field scrolls to keep the cursor in view.
- While a clone runs, SIGTERM and SIGINT stop it as SIGHUP does (Python
  catches SIGHUP only).
- The Settings screen shows the settings as each 2 s refresh read them, so
  a file fixed meanwhile shows; Python reads them when the screen opens
  and after each save.
- One command, `itm`; the Python package also installed it as
  `inbox-task-manager`. Both names still count for the process-name rule.
- No `ITM_THEME`: the switcher draws with the terminal's named colors
  (Textual themes have no counterpart).
- A snooze time only GNU `date` reads, typed in the snooze dialog or the
  form, is read by a worker; keys typed in those milliseconds are dropped.
  The Python switcher ran `date` on its event loop, which queued them.
- `itm --version` says 0.3.0: the first Rust release follows the Python
  0.2.0, so packages do not look like a downgrade.
